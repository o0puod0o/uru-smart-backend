Endpoint Comparison: เดิม vs ใหม่ LRD
====================================

วันที่ทดสอบ: 14 สิงหาคม 2026


1) สรุปสั้น ๆ
-------------

endpoint เดิมกับ endpoint ใหม่ต่างกันพอสมควร เพราะข้อมูลมาจากคนละ database และคนละ schema

endpoint เดิม:

- /api/educations
- /api/researches
- /api/me/external-profile

ใช้ข้อมูลจาก expert2 หรือข้อมูลรวม

endpoint ใหม่:

- /api/lrd/researchs
- /api/lrd/papers
- /api/lrd/projects
- /api/lrd/educations
- /api/lrd/proposals
- /api/lrd/facultys
- /api/lrd/branchs
- /api/lrd/paperindexs

ใช้ข้อมูลจาก lrdsystem2 โดยตรง

4) ทดสอบ Owner Protection
-------------------------

ทดสอบ user ปัจจุบัน:

current_user_researcher_id = 881

เลือก paper ของคนอื่น:

{
    "other_paper_id": 128,
    "other_researcher_id": 1440
}

ลอง update paper ของคนอื่น:

PUT /api/lrd/papers/128

Result:

{
    "update_other_status": 404
}

ลอง delete paper ของคนอื่น:

DELETE /api/lrd/papers/128

Result:

{
    "delete_other_status": 404
}

หมายความว่า:

- อ่าน paper ของคนอื่นได้
- แต่แก้/ลบของคนอื่นไม่ได้
- ได้ 404 เพราะ backend query เฉพาะ record ที่ researcher_id ตรงกับ user login
- วิธีนี้ปลอดภัย เพราะไม่เปิดเผยว่า record มีอยู่จริงหรือไม่


5) ตารางเปรียบเทียบ
-------------------

| เรื่อง | Endpoint เดิม | Endpoint ใหม่ LRD |
|---|---|---|
| Database | expert2 / ข้อมูลรวม | lrdsystem2 |
| Owner key | id_card | researcher_id |
| ชื่อ field title | name / course | title_th / projectname |
| อ่านของคนอื่น | ผ่าน external-profile บางส่วน | scope=all |
| แก้ของคนอื่น | ไม่ได้ | ไม่ได้ |
| สร้างข้อมูล | ใช้ id_card จาก token | ใช้ researcher_id จาก token |
| เหมาะกับหน้า | profile/expert portfolio | research module / paper / project |


6) ต่างกันเยอะไหม
-----------------

ต่างกันระดับกลางถึงเยอะในเชิง response shape

เพราะ:

1. endpoint เดิมใช้ expert2
   - owner คือ id_card
   - field เช่น name, course, university

2. endpoint ใหม่ใช้ lrdsystem2
   - owner คือ researcher_id
   - field เช่น title_th, title_eng, projectname, publicyear

แต่ frontend ไม่ต้องเปลี่ยนเรื่อง auth/token

เหมือนเดิม:

Authorization: Bearer <token>

ต่างหลัก ๆ คือ:

- URL endpoint
- field ใน response
- query params scope=mine/all


7) ผลกระทบต่อ Frontend
----------------------

สิ่งที่ใช้เหมือนเดิม:

- login
- token
- header Authorization
- pagination shape โดยรวม

สิ่งที่ต้องเพิ่ม/แก้:

- เพิ่ม API service สำหรับ /api/lrd/*
- mapping field ใหม่ เช่น title_th แทน name
- เพิ่ม scope=all สำหรับหน้า list/search รวม
- ปุ่ม edit/delete ควรแสดงเฉพาะ item ที่ researcher_id ตรงกับ user ปัจจุบัน


8) สรุปสุดท้าย
--------------

endpoint เดิมยังใช้กับข้อมูล expert/profile ได้

endpoint ใหม่ /api/lrd/* ใช้กับ module งานวิจัยฝั่ง lrdsystem2

อ่านงานคนอื่นได้ผ่าน scope=all
แต่แก้/ลบได้เฉพาะงานที่ researcher_id ตรงกับ user ที่ login เท่านั้น
