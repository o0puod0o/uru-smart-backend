============================================================

2.1 Login ผ่าน backend โดยใช้ email/password

POST /api/auth/login
Content-Type: application/json

Body:

}

  "user": {

3) SSO จริงแบบ REDIRECT CALLBACK
============================================================

ค่าที่อาจารย์ให้:
clientId = urusmart
clientSecret = state
redirectUri = https://urusmart.uru.ac.th/auth/callback

Flow ที่ควรเป็น:
1. Frontend เปิดหน้า SSO จริง
2. User login ด้วย email @live.uru.ac.th
3. SSO redirect กลับมาที่:
   GET https://urusmart.uru.ac.th/auth/callback?code=...&state=...
4. Backend เอา code ไปแลก token กับ SSO
5. Backend ดึง userinfo จาก SSO
6. Backend เอาเลขบัตรประชาชนไปดึง profile จาก expert
7. Backend sync user เข้า database กลาง
8. Backend redirect/ส่ง mobile token กลับให้ frontend

สถานะปัจจุบัน:
- API token flow พร้อมแล้ว
- ยังต้องเพิ่ม/ยืนยัน route GET /auth/callback ก่อนใช้ redirect flow จริง
- ยังต้องรู้ SSO authorize URL, token URL, userinfo URL จริง

4) USER PROFILE
============================================================

GET /api/me
Authorization: Bearer {mobile_bearer_token}

ใช้ดึง profile ของ user ที่ login อยู่

PUT /api/me
Authorization: Bearer {mobile_bearer_token}
Content-Type: application/json

ใช้แก้ไขเฉพาะข้อมูลที่ mobile app เป็นเจ้าของ เช่น phone, line, facebook, website, bio, address ฯลฯ
ไม่ควรแก้ข้อมูล master จาก SSO/expert เช่น เลขบัตร, ชื่อ, นามสกุล

POST /api/me/photo
Authorization: Bearer {mobile_bearer_token}
Content-Type: multipart/form-data

ใช้ upload รูป profile ฝั่ง mobile app

DELETE /api/me/photo
Authorization: Bearer {mobile_bearer_token}

ลบรูป profile ฝั่ง mobile app

GET /api/me/external-profile
Authorization: Bearer {mobile_bearer_token}

ดึงข้อมูล profile จาก expert/external profile ตาม token user
