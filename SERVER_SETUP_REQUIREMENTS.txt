MOBILE BACKEND - PRODUCTION SERVER SETUP REQUIREMENTS
================================================================================

PHP VERSION: 8.2
LARAVEL VERSION: 10.10+
NODE VERSION: Latest
DATABASE: MySQL 8.0

REQUIRED DEPENDENCIES
================================================================================

- mbstring (String encoding - Thai character support)
- zip (Archive handling)
- exif (Image metadata)
- pcntl (Process control)
- bcmath (Mathematical precision)

PHP Packages (from composer.json):
- laravel/framework ^10.10
- laravel/sanctum ^3.3 (Token-based authentication)
- guzzlehttp/guzzle ^7.10 (HTTP client for Gemini API)

Node Packages (optional):
- npm (included in Dockerfile)

================================================================================
ENVIRONMENT VARIABLES FOR PRODUCTION
================================================================================

CRITICAL - Must change before deployment:

APP_ENV=production (NOT local)
APP_DEBUG=false (Hide detailed errors)
APP_URL=https://your-domain.com
APP_KEY=base64:... (Generate: php artisan key:generate)
GEMINI_API_KEY=your-api-key-here

Database:
DB_HOST=your-mysql-server (NOT localhost)
DB_PORT=3306
DB_DATABASE=mobile_db_prod
DB_USERNAME=prod_user (Create separate production user)
DB_PASSWORD=strong_password_here (Use strong password)

SSO Integration:
SSO_BASE_URL=https://your-sso-server
SSO_CLIENT_ID=3
SSO_CLIENT_SECRET=your_secret_here

Caching & Queue:
CACHE_DRIVER=redis (or file)
QUEUE_CONNECTION=sync (or redis for background jobs)
SESSION_DRIVER=file (or redis)

Email (if needed):
MAIL_MAILER=smtp
MAIL_HOST=your-smtp-server
MAIL_PORT=587
MAIL_USERNAME=your-email
MAIL_PASSWORD=your-password
MAIL_ENCRYPTION=tls

================================================================================
STORAGE & FILE PERMISSIONS
================================================================================

Directories that must be writable:
- storage/app/public/photos (User photo uploads)
- storage/logs (Application logs)
- bootstrap/cache (Laravel cache files)

Set permissions:
chmod -R 775 storage bootstrap/cache
chown -R www-data:www-data storage bootstrap

Create storage symlink:
php artisan storage:link
(Creates: public/storage → storage/app/public)

================================================================================
PRE-DEPLOYMENT CHECKLIST
================================================================================

1. Install Composer dependencies:
   composer install --no-dev --optimize-autoloader

2. Generate application key:
   php artisan key:generate

3. Run database migrations:
   php artisan migrate --force

4. Create storage symlink:
   php artisan storage:link

5. Optimize for production:
   php artisan config:cache
   php artisan route:cache
   php artisan view:cache

6. Clear all caches:
   php artisan cache:clear
   php artisan config:clear

7. Verify file permissions:
   ls -la storage bootstrap/cache

- Port 80 (HTTP) → Redirect to 443

- Redis: 6379 (if used)

================================================================================
DATABASE SETUP
================================================================================

Create production database:
CREATE DATABASE mobile_db_prod CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

Create production user:
CREATE USER 'prod_user'@'localhost' IDENTIFIED BY 'strong_password';
GRANT ALL PRIVILEGES ON mobile_db_prod.* TO 'prod_user'@'localhost';
FLUSH PRIVILEGES;

Run migrations:
php artisan migrate --force

Run seeders (if needed):
php artisan db:seed

================================================================================
NGINX CONFIGURATION EXAMPLE
================================================================================

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate /path/to/certificate.crt;
    ssl_certificate_key /path/to/private.key;

    root /var/www/public;
    index index.php index.html;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass 127.0.0.1:9000;
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location ~ /\.ht {
        deny all;
    }
}

# Redirect HTTP to HTTPS
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$server_name$request_uri;
}

================================================================================
IMPORTANT NOTES - ข้อสำคัญที่ต้องรู้
================================================================================

⚠️  API KEY SECURITY
    - GEMINI_API_KEY ในไฟล์ .env ปัจจุบันเป็น public (อยู่ใน git)
    - ต้องหมุน/สร้าง API key ใหม่ก่อน deploy production
    - เก็บ API key ไว้ใน environment variables เท่านั้น ห้ามเก็บใน git

⚠️  APP_KEY GENERATION
    - APP_KEY ต้องสร้างใหม่สำหรับแต่ละ server
    - รัน: php artisan key:generate
    - ไม่ควร reuse APP_KEY จากเซิร์ฟเวอร์อื่น

⚠️  DATABASE BACKUPS
    - ต้องมี automated backup (ทุกวัน หรือ ทุกชั่วโมง)
    - เก็บ backup นอก server หลัก
    - ทดสอบ restore backup อย่างน้อยเดือนละครั้ง

⚠️  SSL/HTTPS CERTIFICATE
    - ต้องใช้ HTTPS สำหรับ production
    - แนะนำใช้ Let's Encrypt (ฟรี)
    - Auto-renewal ต้องตั้งค่า cron job

⚠️  DATABASE PASSWORD
    - ห้ามใช้ "secret" ในชื่อ password
    - ใช้ password ที่ strong และ random
    - เก็บ password ในที่ปลอดภัย (secret manager, vault)

⚠️  LARAVEL DEBUG MODE
    - ห้ามเปิด APP_DEBUG=true ใน production
    - เปิดเฉพาะ local/staging
    - Debug mode เผย sensitive information (file paths, database errors, etc.)

⚠️  LOG FILES
    - ตรวจสอบ storage/logs อย่างสม่ำเสมอ
    - ตั้ง log rotation เพื่อไม่ให้พื้นที่เต็ม
    - Archive old logs

⚠️  PHOTO STORAGE PERSISTENCE
    - ต้องตั้งค่า storage volume ให้ persistent
    - ไม่ใช้ ephemeral storage เพราะรูปจะหายเมื่อ restart
    - ถ้าใช้ Docker ต้อง mount volume ให้ถูกต้อง

⚠️  SSO SERVER DEPENDENCY
    - Mobile backend ต้องติดต่อ SSO server ตลอดเวลา
    - ถ้า SSO server down → Mobile app ไม่สามารถ login ได้
    - ต้องมี monitoring & alert สำหรับ SSO server health

⚠️  GEMINI API RATE LIMITING
    - Free tier มี rate limit (queries per minute)
    - Paid tier แนะนำสำหรับ production
    - ต้องมี error handling สำหรับ rate limit errors

⚠️  CORS & SECURITY HEADERS
    - ตั้ง CORS_ALLOWED_ORIGINS ให้ถูกต้อง
    - เพิ่ม security headers (Content-Security-Policy, X-Frame-Options, etc.)
    - ห้ามตั้ง CORS_ALLOWED_ORIGINS=* ใน production

⚠️  TOKEN EXPIRATION
    - Sanctum token ต้องมี expiration time
    - ตั้ง SESSION_LIFETIME ให้เหมาะสม (ไม่ใช่ unlimited)
    - Token refresh mechanism ต้องมี

⚠️  MONITORING & ALERTING
    - ต้องมี monitoring สำหรับ:
      * Server health (CPU, RAM, disk)
      * Application errors (check logs daily)
      * Database performance
      * API response time
      * Gemini API quota usage
    - ตั้ง alert เมื่อมีปัญหา

⚠️  MAINTENANCE MODE
    - สำหรับ database migrations หรือ updates
    - รัน: php artisan down
    - รัน: php artisan up
    - ควรมี maintenance window notification

⚠️  FILE UPLOAD VALIDATION
    - ต้องตรวจสอบ file size & type ก่อนรับ
    - scan for malware ถ้า possible
    - ตั้ง max upload size ใน nginx & PHP
